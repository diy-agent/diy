## 1. 宏观定位：AI 事实标准库 (Ground Truth Knowledge Base)

**问题背景**：
AI Agent 在进行代码辅助时，常常受限于模型内部的知识衰减和版本幻觉（如用 Pandas 1.0 的语法指导 2.0 的工程）。通过网络现查文档不仅耗时，而且充满噪音。

**`diy-ref` 的核心使命**：
将“依赖同步”从单纯的文件操作，升级为构建项目的**事实标准库**。
- 为 Agent 提供一个局部的、版本绝对锁定的、高信噪比的代码与文档上下文。
- 当 Agent 询问“这个库怎么用”、“源码是怎样的”时，**绝对禁止网络猜测**，必须强制通过 `diy-ref` 模块索引直接读取本地缓存。

---

## 2. 核心命名与配置设计

### 2.1 模块与 Skill 命名
- **模块名称**：`diy-ref` (作为 `diy` 的子品牌功能模块)。
- **生成的 Skill 名称**：`diy-ref` (`.agents/skills/diy-ref/SKILL.md`)。

### 2.2 项目配置 (`diy.yaml`)
将原有的 `sources` 字段升级为 `references`，并支持简洁的协议前缀声明（类似于 pnpm 或 uv 的体验），提高人机交互的可读性。

```yaml
# diy.yaml 示例
references:
  # 惯例极简格式： <协议>:<包名或路径>[@<版本/标签>]
  - npm:react@18.2.0
  - git:github.com/agentclientprotocol/agent-client-protocol@main
  - git:github.com/vitest-dev/docs-cn
  # (未来扩展数据集等)
  # - dataset:s3://bucket/stock-data.csv
```

### 2.3 锁定文件设计 (`ref.lock.json`)
为了区分“人工编写文件”与“工具生成文件”，防止误覆盖，并提供清晰的溯源信息：
- 原 `.diy/ref/ref.lock.json` 更名为 `.diy/ref.lock.json`。
- 新增 `_generated` 元数据块。

```json
{
  "_generated": {
    "desc": "This file is automatically generated by `diy sync`. DO NOT EDIT MANUALLY.",
    "version": "1.0",
    "created": "2026-05-27T10:00:00Z",
    "updated": "2026-05-27T10:00:00Z"
  },
  "mirrorRoot": "~",
  "workspaces": [],
  "references": []
}
```

## 3. 存储与预处理策略 (Preprocessing & Indexing)

### 3.1 无干扰全局存储
所有通过 `diy sync` 获取的代码库，统一存放于 `~/.diy/ref/`，项目内 **0 软链接**。IDE 通过 `tsconfig.ide.json` 绝对路径映射。

### 3.2 摘要文件生成 (AI-Readable Summary)
原始代码库信息熵太高，Agent 直接 `grep` 容易迷失。需要在同步后进行轻量级预处理。

- **命名规范**：在下载好的依赖根目录下生成带 `diy-` 前缀的文件，避免与原项目文件重名（如 `diy-summary.md` 或 `diy-index.md`）。
- **短期实现 (MVP)**：`sync` 结束后，自动执行类似 `tree -L 2` 的操作或提取顶层目录/核心文件，写入 `diy-summary.md`。
- **中期规划**：研究和引入 `CodeGraph` (或 `scip` / `universal-ctags` 等 AST 工具)，提取类/函数声明写入 `diy-index.md`。Agent 只需阅读此索引，即可精准知晓 API 和源码位置。

## 4. 动态 Skill 生成 (Dynamic Skill)

这是 `diy-ref` 发挥作用的关键。`sync` 执行完毕的最后一步，是自动生成（或覆盖）针对当前项目的 Skill 引导文档。

**生成路径**：`.agents/skills/diy-ref/SKILL.md`

**SKILL.md 模版设计意图**：
```markdown
---
name: diy-ref
description: >
  当你需要查阅第三方库的 API、类型定义或项目锁定的外部参考资料时，必须调用此 skill。
  触发词：查文档、看源码、API怎么用、数据结构是什么。
---
```

## 5. 新会话实施路径 (Implementation Roadmap)

接手此任务的 Agent 请按照以下步骤在 `packages/diy-cli.py/src/diycli/_sync.py` 等文件中进行改造：

- [ ] **Step 1: 升级配置解析**。修改 `diy.yaml` 解析逻辑，支持解析 `references` 字段，并编写 `npm:` 和 `git:` 等快捷协议前缀的解析正则。
- [ ] **Step 2: 重构锁文件**。更新 `build_ref_lock` 和 `write_ref_lock_file` 函数。引入 `_generated` 元数据节点；将文件名从 `ref.lock.json` mv到 `./diy/ref.lock.json`。
- [ ] **Step 3: 实现轻量级预处理**。在 `process_package` 成功 `clone` 代码后，读取其一层或两层目录结构，向其根目录写入 `diy-summary.md`（可先用极简的文件列表实现）。
- [ ] **Step 4: 实现动态 Skill 注入**。在 `sync_dependencies` 流程末尾，新增一个 `generate_dynamic_skill(root_dir, all_deps, sync_results)` 函数，自动写入项目下的 `.agents/skills/diy-ref/SKILL.md`。
- [ ] **Step 5: 测试闭环**。运行 `uv run diy sync -v`，检查 `.diy/ref.lock.json`、缓存库中的 `diy-summary.md` 以及生成的 `SKILL.md` 是否正确。
