# 测试归属规则与清理（现行）

> 2026-11-10 · 任务 ##518。口径：**从需求 / API 黑盒测；一个行为只写一遍；只在三处用替身**。
> 配套文档：`docs/research/ui-testing-strategy.md`（怎么跑得快）、`docs/testing.md`（目录与命令）。

## 1. 三层归属（写之前先判这一条）

| 层 | 放什么 | 判据（问自己） |
|---|---|---|
| **unit** | 纯规则 / 纯函数 / 边界：状态机非法迁移、代价计算、解析、格式化 | 这个失败**只能在**极多前置条件下才露头？（上层要造 10 个对象才能触发它） |
| **core（rpc 层）** | 协议与副作用：方法名、入参校验、错误码映射、真 fs / 真 git / 并发幂等 | UI 层**看不到**这个失败（用户界面上没有任何差异）？ |
| **UI（进程内全栈）** | 用户可观察的行为：点一下变成什么、失败提示、日志是否流出、列表是否更新 | 这句话能写成「用户看到 X 变成 Y」？ |

**唯一的归属判据**：

> 如果把这个用例删掉，而它上层那层已经覆盖 —— **会漏掉什么类型的问题？**
> 答不出具体类型 ⇒ 删。答得出 ⇒ 它就该留在这一层，并在测试名里写清那个类型。

## 2. 铁律

1. **同一行为不写三遍**。Agent 这类对象：规则边界留 unit、协议与副作用留 core、
   「点了启动 → 界面变成运行中 → 日志出现」只写在 UI 层（它天然覆盖了 core 的调用路径）。
2. **只从需求 / API 黑盒测**。不测私有函数、不测内部状态字段、不测 class 结构。
   重构不该让测试变红；测试变红就意味着行为变了。
3. **替身只许三处**：LLM（黄金回放）、`spawn`（拉起真实例 = fake spawn）、时间（可控 clock）。
   其余一律真跑 —— 真 rpc、真 core、真 fs（临时目录）、真 git（临时仓）。
4. **新增或修改的测试只允许出现在一层**：PR 里跨层重复由 review 打回。
5. **断言用户/调用方能看到的**：DOM 文本与角色、返回值、盘上文件、注册表记录、错误码。
   不断言：内部计数器、私有字段名、渲染次数（除非被测对象就是性能）。

### 3.1 删除的四条判据（满足任一即可进候选）

- **A 纯取值**：只断言格式化 / 默认值 / 字段映射，且这些值在 UI 或 core 行为里已经间接可见；
- **B 上层已覆盖**：同一句话在 `core-intent/` 或未来的 UI 全栈里已有断言；
- **C 测实现**：断言私有函数、内部字段、调用次数、渲染次数（不是性能测试）；
- **D 无独特断言**：把断言逐条读一遍，去掉重复的，剩不下任何「会失败的行为」。

### 3.2 第一批候选（按名字初筛，删前必须逐条核）

> ⚠️ 这些是**候选**，不是判决。删前做两件事：① 打开文件确认无 B 以外的独特断言；
> ② 跑一次全量确认删掉后没红（红的说明上层没覆盖，改成写进上层再删）。

## 4. 复核工具（不靠记忆，靠跑）

```bash
# 每个 core 单测的「规模 + 断言数 + 顶层 describe」—— 一眼看出谁是纯取值
cd apps/diy-app/tests/core
for f in *.test.ts; do
  n=$(grep -cE "expect\(" "$f")
  d=$(grep -m1 -oE 'describe\("[^"]+' "$f" | cut -c11-)
  printf "%3s 断言  %-46s %s\n" "$n" "$f" "$d"
done | sort -n
```

判定：**断言 ≤ 2 且 describe 名是「格式化 / 默认值 / 映射」类 ⇒ A 类候选**；
断言多但全是 `toBe(x)` 常量往返 ⇒ 也按 A 处理。

## 5. 清理的执行顺序（低风险优先）

1. **A 类**（纯取值）：批量删，遇到红的改成上层断言后删；
2. **C 类**（测实现）：删或换成返回值断言；
3. **B 类**：先确认上层覆盖，再删；
4. **`ui-intent/` 整批**：迁一批（10–15 条覆盖启停 / 选中 / 页签 / 只读外部实例 / 文件读写），其余删；
5. 最后再回头看 `services/`：它们多是“起进程 + 打 rpc”，能进程内化的都换成 mem transport。

每一步之后跑一次全量并记录耗时 —— 目标是**测试总量下降、全量时间不涨、红的一个不少**。
