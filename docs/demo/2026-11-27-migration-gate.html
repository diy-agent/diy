启动闸门：由「数据版本」决定进不进迁移页 diy2 · ##41 · 2026-11-27

一、入口是怎么决定的

进程启动→ 只读探库
probeMigration（不 openStore）→ 有待迁移？→ 装配「迁移态」app
只服务迁移页，其余 503 / 直接装配真 app
工作台

迁移本身在子进程跑（同步迁移会卡事件循环），迁完同端口换成真 app。闸门只决定「要不要先站在门口」。

二、病根：闸门用错了判据

旧闸门：migrationPlan().some(item => !item.done)

done() = 数据体检（这张表还在吗 / 还有占位值吗 / 每房是不是只剩一个成员）
  • 数据一变回「不像迁过了」，done() 就翻回 false
  • 于是已迁完的库每次启动都回迁移页
  • 点「开始迁移」又被 run() 跳过（已记账的非 converge 迁移不重跑）
  • 结果：页面永远转圈、无进展 —— 人真卡死，无解

新闸门：missingMigrations()（读 schema_migrations）

版本表 = 「这条迁移跑过没有」，这才是「迁没迁」的真源
  • 版本表管「要不要拦」，done() 只用于 run() 的基线判断
  • unknown（库里记账、代码里没有的 id，切分支遗留）只警告，不拦
  • applied 只数代码认得的 id → 不再出现「17 / 16」
  • 收敛类（converge，清占位值）照常每次启动复查 —— 它永远不该卡启动
