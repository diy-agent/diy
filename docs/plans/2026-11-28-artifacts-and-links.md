# 产物与链接：目标执行中的文档 / lab 该挂在哪（2026-11-28）

> 起因：用户问「类似 `file://…/42-bot-session-domain/docs/plans/2026-11-28-bot-session-domain.html`
> 这种执行中目标的阶段性文档、或起好的 lab 链接，应该怎么有效地挂载？算账本的一部分吗？」
> 并提示「问链接、起 lab 的发言非常多，说明是个需求」。本文先把**发言数据**摆出来，再给设计。

## 一、数据（生产 home `~/.diy2`，2698 条房间消息）

| 口径 | 人类发言 | bot 发言 |
|---|---|---|
| 总数 | 1360 | 1338 |
| 提到 链接 / 地址 / 端口 / lab / 文档路径 | **131（9.6%）** | — |
| 要求「起 lab / 启动实例 / 重开」 | 30 | — |
| 直接贴一个 `http://127.0.0.1:…` 让人看 | **50** | — |
| 抱怨链接坏了 / 白屏 / 打不开 | 10 | — |
| 要阶段性文档（`.html` / `docs/plans/…`） | 25 | — |
| 消息里带 localhost 链接 | — | **180（13.5%）** |

一句话：**约十分之一的人话是在跟「一屏东西」打交道**，而 bot 那边每 7 条就有 1 条在贴地址。
这不是偶发偏好，是每次交付都要走一遍的动作。

## 二、这 131 条其实在说四件事

1. **起 lab 看效果**（30 条）——「启动lab服务我看下」「开lab链接给我」「先起 lab 看效果」
   要的不是一段描述，是**能点开的一屏**。文字说「已经改好了」不构成交付。
2. **贴 URL 当坐标**（50 条）——「http://127.0.0.1:5192/room/xxx 这个任务现在啥情况」
   URL 在这里不是「文件」，是**「我们在说哪一屏」的指针**，和「第 3 段代码」同级。
3. **链接坏了**（10 条）——「lab挂了，麻烦重启动一下」「http://127.0.0.1:62766服务挂了」
   「空白页面 file:///private/tmp/model-config-demo.html」。链接会**烂**，而烂了没人知道。
4. **要阶段性文档**（25 条）——设计稿、review 稿、demo 页。

## 三、根因：现在的「链接」只是字符串，没有身份

三段断裂，每段都真发生过：

| 断在哪 | 现象 | 实例 |
|---|---|---|
| **worktree 里的文档** | 删 worktree ⇒ 链接当场死 | 本次清理删了 9 个 worktree；用户刚贴的 `…/42-bot-session-domain/…html` 正是这种引用 |
| **lab 链接没有生命周期** | 实例停了 / 端口换了 / 被 `diy2 stop` 了，聊天里那条地址还是原样蓝字 | 「lab服务挂了」「62766服务挂了」 |
| **链接散在正文里** | 想找「上次那个 lab 的地址」只能翻聊天记录 | 「这个任务现在啥情况，job卡住了？job的ui形态貌似有点问题」 |

结论：**链接必须有身份（实体）+ 状态（活/死）+ 归属（哪条需求 / 哪个目标）**，
只做「把 URL 加粗成可点」解决不了任何一条。

## 四、设计：产物是一等公民，但**不新建第二本账**

### 4.1 数据形状

- **产物 = 一条事件**（`events` 表，`kind=artifact`，带 `unit` 指向），append-only；
- **状态不存列，靠派生**：lab 类产物的死活由实例注册表（`diy2 list` / run registry）与端口探测算，
  文档类产物由「文件还在不在 / 是否进了 main」算；
- 这样既不引入会跟真源打架的 `artifact_state` 字段，也不会出现「账本说有、机器上没了」。

理由与步骤层那次一致：**能被派生的事实不落库**；库里只留「人/agent 说过这里有东西」这一步不可重建的信息。

### 4.2 三类产物，三种寿命

| 类型 | 例 | 寿命 | 失效怎么办 |
|---|---|---|---|
| `doc` 阶段性文档 | `docs/plans/xxx.md` / demo `.html` | 跟仓库走 | 没进 main 的标「临时」；**禁止**把 worktree 内 `file://` 当交付 |
| `run` 跑起来的实例 | lab / staging / electron | 跟进程走 | 派生「运行中 / 已停止」，一键重开（起 background job） |
| `evidence` 证据 | PR / commit / job / 截图 | 永久 | 链接稳；job 输出按保留策略 |

### 4.3 谁来挂：**宿主自动捕获**，不指望模型记得

- 任何 bot 消息、工具输出里出现 URL（`127.0.0.1:port`、`docs/plans/*.html`、PR 链接、job id）
  → 宿主抽出来，挂到**本轮 doing 的那条需求**上（`source = 本轮触发消息`，模型填不了也删不掉）；
- 模型仍然可以显式「这条产物属于那条需求」覆盖归属；
- 人贴 URL 时反向解析：`/room/<id>` → 房间、`docs/…` → 文档、`localhost:port` → 实例，
  给一个「挂到当前目标」的动作（而不是让人再描述一遍）。

### 4.4 汇报形状固定（这是最便宜的一刀）

起完 lab / 写完阶段性文档，固定三行，不靠人问：

```
地址：http://127.0.0.1:58062/room/<id>（点开就是这一屏）
用途：两层账本的左栏层级 + 需求详情验收口径
寿命：跟着这个 lab 进程；重启会换端口，我会把新地址补在同一条产物上
```

对应账本里 `run-link-format` 那条需求。今天实测：**用户为了拿到地址平均要追 1~2 轮**。

### 4.5 UI

- **目标详情**加「产物」块（文档 / 链接 / 截图 / 报告 / PR），按类型分组，行内带状态点；
- **左栏目标行**给一个小徽标（`3 产物`），点开才看，不占宽度；
- 聊天里的链接：默认**新窗口**打开（用户 2026-11-27 明确提过，本窗口打开会把对话顶掉）；
- `run` 类产物失效时卡片变灰 + 「重开」按钮（重开 = 起一个 background job，地址回填同一条产物）。

## 五、先做哪三刀（按性价比）

1. **汇报形状 + 结构化出口**（最便宜）：lab / 文档类工具返回 `{url, purpose, ttl}`，正文三行照抄它 ——
   消灭「再问一遍地址」。
2. **宿主自动捕获 + 目标产物区**：不实现这步，前一步只是「写得好一点」，仍然没有归属、不能回看。
3. **文档产物必须进 main 或产物库**：`docs/plans/*.md` 随 PR；demo `.html` 若要给人看，就复制到
   `docs/demos/` 并一起进 PR，**不把 worktree 内路径当链接发**。

## 六、验收口径

- 任意一条需求点开，能看到「它产出了什么」（文档 / 跑起来的实例 / PR），失效的标出来；
- 起 lab 后的回复**不需要人再问地址**，且地址是结构化字段（不是正文里的一段文字）；
- 删掉 worktree 之后，历史里那些链接**不再是唯一副本**（至少 main 里 或 产物库里还活着）。

## 七、没做的（留档）

- 产物是否要做版本（同一文档多稿）：先不做，靠 git 历史；
- 截图的存放：跟 `doc` 同类，落 `~/.diy2/artifacts/<unit>/`，不进 git；
- 跨任务「这件事的所有产物」：等 `promote-to-task`（目标提升为任务）落地后再统一。
