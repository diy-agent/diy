effort × model：数据结构与 UI 处理

数据来自真 ~/.diy/diy2/data/models.dev.json（292 provider）。每个模型的推理能力由 reasoning(bool) + reasoning_options(数组) 描述。当前问题：我们 catalog 投影时只留了 name/limit/cost，把 reasoning_options 丢了，所以 UI 硬编码 5 档、跟模型无关。 本 demo 展示 5 种真实形态各该怎么呈现。不加表 —— 数据本就在 models.dev 快照里。

形态分布（全库）： effort 档位 4402 toggle 588 budget_tokens 429 [] 空但 reasoning=true 944 无字段 reasoning=false 1392
type = effort

离散档位（各有自己的 values）

sandbase / openai/gpt-5.6-terra
原始 models.dev 数据
{
  "reasoning": true,
  "reasoning_options": [
    { "type": "effort",
      "values": ["none","low","medium",
                    "high","xhigh","max"] }
  ]
}
UI：选项按钮组 = values 原样列出
换模型默认选 values[0] = none。另一模型 gpt-oss-20b 只有 low/medium/high → 只画 3 颗按钮，默认 low。档位随模型变，不是固定 5 档。
type = toggle

关键规则（待你拍板后实现）

换模型默认取第一个 effort：选 effort 型模型 → 自动写 values[0]（如 gpt-5.6 是 none、gpt-oss 是 low）。 toggle / budget_tokens / 空 / 无 → 没有"第一个 effort"，默认存 null（不带参数）。
没有"跟随"档：去掉当前 UI 里的"跟随"按钮。旧描述"跟随模型缺省"语义上 = 存 null，但不再单独占一档 —— 非 effort 模型直接不显示推理强度控件。
旧值处理：已存的 medium/low/high 保留不删；UI 显示时若该值不在当前模型候选里，高亮让用户重选（不擅自改库）。
