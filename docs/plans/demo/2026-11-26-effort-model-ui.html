dsh 怎么做 & 我们怎么"全内化"

dsh（deepseek-harness，源码 ~/git-ref/deepseek-harness）把模型推理能力建模成 LlmModelReasoningInfo { efforts[], defaultEffort? }，UI 只列选项。那个"缺省"就是下面这条规则：

// dsh: packages/acp/acp/src/model-control.ts（简化）
options = info.reasoning.defaultEffort === undefined
  ? [{ value: '', name: 'Provider default' }, ...efforts]  // 没声明默认 → 多一项"交给服务商"
  : [...efforts]                                                       // 有默认 → 不显示，已内化进某个 effort
// 选 "Provider default" ⇒ reasoningEffort 字段整个不传（undefined）
dsh 的"缺省" = "Provider default"：只有模型没声明 defaultEffort 时才出现，选中 = 不带该参数交给 provider。 deepseek 自己声明了默认（high/low/max/off），所以它的选项里没有这一项。effort 档位每个模型不同，全从模型信息来。
我们的方案（用户 2026-11-26 定）：恒显示「缺省」占位，认知与 dsh 一致。 模型信息里解析出 efforts[]；UI 永远先列一颗「缺省」（= 存 null，不带参数交给 provider，等同 dsh 的 Provider default）， 后面跟该模型的 efforts 档位。即便模型没有 effort（toggle / budget / 空 / 无推理），也显示「缺省」占位符，只是没有其它档位。 换模型时默认选第一个 effort（若有），可随时点「缺省」回退。
存储不变 + 旧值校验：仍是 bot_roles.reasoning_effort TEXT 一个字符串，不加表；null = 「缺省」。旧值保留； 若当前模型 efforts 里没有这个值，面板里高亮提示重选（不擅自改库）。
