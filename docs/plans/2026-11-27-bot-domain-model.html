bot profile → bot 实例

2026-11-27 v2 · 按你的澄清重写：不拆 persona 层、没有 primary_flag

只有两层。profile 是配置（哪种 bot），实例是运行体（这个 room 里的那个 bot + 它的 session log）。 人设就是 profile 自己的指令，不单列一层。

一、两层

bot profile —— 配置

指令 · 名字 · 颜色 · 模型 · runtime

按 domain 归属：全局 / 项目 / 任务

跨 room 复用，本身不跑

bot_roles（未来改名 bot_profiles）

bot 实例 —— 运行体

= profile × room

拥有自己的 session log

「任务 bot」= 某实例 + 它的 session log

session_state(entity_id, bot_role_id)
profile ──在某个 room 里出现──▶ 实例（+ session log）

二、两种 bot

沟通型

参与对话：进成员列表、可 @、有 session log

例：项目助手 / 任务 bot / 小满

工具型

不参与沟通、不可 @，只被调用跑一下

例：job 之类

三、为什么现在看着很乱

room 的成员是「该 type 下所有 profile」派生出来的，不是配的：

// apps/diy2/server/app.ts
function membersOf(type) { return membersOfType(listRoles(), type); }

// 等价于 roles.filter(r => r.type === type)

于是每个 project room 都有 4 个 bot（项目助手 / diy / cops / 小满），每个 task room 都有 3 个。 目标：room 常态只有自己的 bot。

四、会议：两种形态（等你拍板）

前提一样：开的会拉的都是已有的 bot 实例，不 new 新 bot；room 常态只有自己。

形态怎么做好处代价
甲 任务 room 本身是私聊；点「开会」切到本任务的会议室（另一实体），拉人，开完关闭回私聊 私聊与会议在实体层分开；会议有独立起止与归档 多一层实体 + UI 切换；跨 room 引用
乙 不区分私聊/会议：同一 room 临时拉人，开完删掉参会人，room 回到只有自己 少一层实体，不切 UI，实现简单 成员动态；「当时谁在场」要靠快照

注意：session 是按 bot 走的（一个 bot 一条连续 session、消息标 room），所以两种形态的开销一样 —— 差别只在「会议是不是一个独立 room 实体」。
