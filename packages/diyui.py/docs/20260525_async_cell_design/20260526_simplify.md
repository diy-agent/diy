# Async Cell 简化 + 修复记录

日期：2026-05-26
状态：简化完成，demo 仍有已知问题

## 变更概要

### 删除 sync→async 升级路径

移除了 `_upgrade_to_async`、`_drive_generator_sync_continue` 和 `_gen_instance` 字段。
`_drive_generator_sync` 遇到 awaitable 改回 `warnings.warn`。

- _scope.py: 577 → 444 行 (-133, -23%)
- 方法数: 21 → 18
- 动机：设计文档 SUMMARY.md 已指出升级路径维护成本高，"半路升级"引入双 finally 清理规则，容易出错

### 修复 `async def` generator cell 支持

三个 bug 修复，之前 `async def` generator 从未真正工作过：

1. **`cell` 装饰器**：`isgeneratorfunction` → `isgeneratorfunction or isasyncgenfunction`
   - `async def` generator 被 `isgeneratorfunction` 判为 False，走到 `_execute_cell` 当成普通函数执行

2. **`_drive_generator_async`**：Python `async_generator` 没有 `send()` 方法
   - 新增 `isasyncgen(gen)` 检测，分支用 `await gen.asend()` + `except StopAsyncIteration`

3. **`enqueue_async` 的 event loop**：Bokeh/Tornado 环境中 `get_running_loop()` 返回空
   - 新增 Tornado `IOLoop.current().asyncio_loop` 回退

### 修复 ScopeViolation 检查方向

`_signal.py` 的跨 scope 检查原逻辑只覆盖 `id(owner) in cell._ancestor_ids`（owner 是 cell 祖先）。
新增反向检查 `id(cell) in owner._ancestor_ids`（cell 是 owner 祖先），覆盖外层 cell 读取子树中 signal 的合法场景。

## 已知问题

### 1. 外层 cell + 内层 async cell 时 ScopeViolation（B/C 路）

Demo 结构：
```
@row.cell()                       # 外层普通 cell
def _():
    with card("A"):
        ta = app.signal(0)         # owner = card_a
        @inner_card.cell()
        async def _():             # cell node = inner_card
            ta.value ...           # 应合法：card_a 是 inner_card 的父
```

A 路正常，B/C 路点击时 `ta.value / tb.value` 访问仍报 ScopeViolation。
检查逻辑 `id(owner) in cell._ancestor_ids and id(cell) in owner._ancestor_ids` 理论上应通过，
需排查具体运行时的 `_current_cell_node` 和祖先链值。

### 2. async cell 的 Bokeh 推送时机

`_drive_generator_async` 在 Tornado asyncio_loop task 中运行，yield 组件后 Bokeh 可能不会在每步间推送 UI 更新。
之前 upgrade 路径能"步步可见"是因为 `_drive_generator_sync` 先 sync 驱动了第一个 yield。
纯粹的 `_drive_generator_async` 路径可能需要每步后显式通知 Bokeh document。
