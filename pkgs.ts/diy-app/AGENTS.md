## entry — 入口注入的环境变量

> 入口辨析（谁是客户端、谁起 GUI、**启动器≠客户端**、**变体必须配对**、数据根差异）见**仓库根 AGENTS.md「entry」**。本节只记本包读到什么。

入口脚本只负责**注入环境变量**，业务统一由 `src/runtime.ts readRuntimeConfig()` 读取组装，不做路径/模式派生。

| 入口 | 跑什么 | 注入 |
|------|--------|------|
| `./diy.sh`（仓库根） | `auto`：`build/<variant>/cli/index.js` 优先，打包源比产物新回退 `tsx src/cli/index.ts`（`DIY_CLI_MODE`） | `DIY_HOME=./build/<variant>/home`、`DIY_VARIANT=preview`、`DIY_CLI` |
| `bin/diy`（发布） | `node build/prod/cli/index.js` | `DIY_HOME=~/.diy`、`DIY_CLI=$0`、`DIY_ENV=production` |
| `scripts/electron-dev.mts`（preview / lab） | `build/<variant>/main/index.mjs` | `DIY_HOME=./build/<variant>/home`（继承来的生产根被拒，见 `env.home`）、`DIY_VARIANT`、`DIY_CLI`、`DIY_DEV_SERVER_URL`、`DIY_ENV=development` |

- `env.home` — `DIY_HOME` 数据根（state/task/**app.port**），缺省 `~/.diy`；**preview/lab / `diy.sh` / `serve` 一律拒绝继承来的 `~/.diy`**（判据唯一定义处 `core/instance-identity.ts::isProdDataHome` ── 真实家目录；撞上后怎么回落见 `core/dev-home.ts::resolveDevHome`；放行需 `DIY_ALLOW_PROD_HOME=1`）。bash 侧（`diy.sh`）同口径归一写法（`cd <dir> && pwd -P`：尾斜杠 / `..` / `./` / 符号链接，是 TS `resolve` 的超集）

- `rule.noemit` — **类型检查绝不 emit**（各包 `noEmit: true`，唯一入口 `./sha.sh check`）。一旦产物落在源码旁，`resolve.extensions` 里 `.js/.jsx` 排在 `.ts/.tsx` 之前 → dev/构建/单测全部静默加载旧产物
- `rule.stdio` — 子进程 stdio 判据是**读端是否一定被排空**：常驻/分离式 spawn 一律 `inherit`/`ignore`；测试侧 `pipe` 必须挂 `data` 监听持续排空。⚠️ **不得**为解析 `DevTools listening on` 而 pipe stderr —— CDP 地址一律读 `DevToolsActivePort` 文件
- `rule.test-home` — 隔离 HOME **用后即删**（`tests/temp-home.ts`）：两套前缀都要管 —— `diy-app-test-*`（electron-test，`stop()` 当场删）与 `diy-desktop-test-*`（`setup.ts` 每测试文件一个，`afterAll` 删；**`process.on("exit")` 在 vitest worker 里不触发** —— 被 tinypool SIGTERM 掐）。删除双校验：必须在 `os.tmpdir()` 下 + 带本套件前缀（`TEST_HOME_PREFIXES`），缺一不可；另有 `sweepStaleTestHomes`（>24h）兜强杀残留。历史代价：曾 4 天积 1583 个 / 2.9GB
- `rule.test-render` — intent 用 `--no-file-parallelism` + `fileParallelism:false`：**单实例串行**（起→测→收），实测 app 并发恒为 1；别改成并发（多实例抢 CPU 会让墙钟判据假红）
- `rule.renderer-io` — renderer **永不直接写文件**，一律经 RPC（如 `diy.task.drafts.*`）
- `rule.check` — 类型检查只准 `./sha.sh check`；**同一变体**的 `preview`/`lab` 运行中勿并发 `tsc -b`/`vite build`/全量 vitest（抢同一 `outDir`，watcher 卡死）。跨变体（preview vs test）不抢——各写 `build/<variant>`
- `rule.agents-chain` — AGENTS.md 链**上界到 `$HOME` 为止**（不进 `/`、`/Users`）；不在 `$HOME` 下时只取工作目录一层
- `rule.budget` — 系统提示词预算 `clamp(模型上下文 × 4B × 5%, 16KB, 64KB)`；超限**拒发不截断**，且早退也必须闭合轮次（stop + noteTurnEnd + 审计）
- `rule.golden` — 改内置模版（`src/main/prompts/defaults.ts`）**必须同步** `tests/fixtures/system.golden.txt`（当前内置模版的逐字节快照）。⚠️ `./sha.sh check` **不含 vitest**，不会替你抓到这类失效 —— 改完模版跑 `npx vitest run tests/core/template-dsl-golden.test.ts`
- `rule.steer-queue` — **会话生成中再发消息不拒绝、改排队**（##306）：入 `SteerQueue`（缺省 **`next-step`** = 下一个模型步边界前整批投，横条可切回 `next-turn`），只回一条排队回执（`kind=error` + `meta.source=queue`，error 块不进 LLM 投影）；条数上限 `maxSteerQueue`（默认 1000，`local/limits.json` / `DIY_LOCAL_MAX_STEER_QUEUE`，超限在 `SteerQueue.add` **抛错**不静默丢）。**UI 两个入口**：输入框发送（`LocalChatPage` 的 `submit` 在 `live` 时本地早退 → 该路径目前只由 CLI / RPC 可达）与横条**留言**（`submitSteer`，同一队列、同一缺省时机 `shared/steer-mode.ts` 的 `DEFAULT_STEER_MODE`）
- `rule.agents-injected` — **本文件会被 `chainOf` 注入 system 提示词**（受 64KB 预算 `SYSTEM_BUDGET_CAP_BYTES` 约束）：长文写 README / 独立文档，这里只留指针
- `rule.turn-lifecycle` — **轮次生命周期独立于消费端连接**（##305）：`agent.local.chat` 虽是 `serverStream`，但**流只是订阅者** —— 驱动在 `LocalAgentManager.driveTurn`（`turns` 注册表持有，与生成器解耦），消费端断开（刷新/切页/关窗/杀 CLI）**只退订、不 abort**（旧行为"`finally` 里 `if(!done) ctrl.abort()`、无人消费即停"已废；改写这块别把生成器当驱动者）。无人消费**继续烧 token**（定案：窗口只是后端的使用窗口），开销由 **`maxSteps`（缺省 200，`DEFAULT_LIMITS.n`）步数上限**自然收口 —— **禁加时间维度的"无人即停"回收**（会误杀正常长任务）；真卡死由人在全局会话视图（导航「会话」`components/SessionOverviewPage.tsx`）手动中断（##308 已落地，见 `find.sessions`）。可见性 = `LocalAgentManager.watchers`（chat 流消费端 + `opsFeed` 订阅**都算**，UI 只走后者）→ `agent.local.running` 的 `subscribers`。⚠️ 摘除靠 **service 层听 RPC 注入的 `signal`**（`withCleanup` 第三参）：断开时 RPC 层调的是 `abort` + `void g.return()`，而 `return()` **排在悬挂的 `next()` 之后**（生成器卡在 `await inner.next()`）⇒ 无事件期间断开根本走不到 cleanup，订阅要等**下一条事件**才释放（`subscribers` 虚高）。**订阅类 serverStream 必须把 `signal` 一路传到 `withCleanup`**（`agent.local.chat` 的 `run.subs` / `ops-feed.subscribe` / `file-watcher.subscribe` **三处已接**，review1-R1 补齐 chat 那条），新增订阅源照办。重连追平走 ops 水位（读侧 ##307）
- `rule.no-silent-catch` — 不要静默吞异常（如切模型曾一律 `catch {}` → 用户以为切了其实没切）
- `rule.log-vs-config` — **落盘日志**（`local/*.jsonl`）读侧宽松（初版紧凑/扩展松散/缺必填即**异常数据**，见 `log-schema.ts`）；**配置真源**（`context.yaml` / `auto-compact.yaml`）读侧出声回落默认、写侧归一 + 原子写，且**不进 localStorage**（有损 + 两进程各持一份）
- `rule.form-toggle` — **表单里的三态控件**：二态开/关用 daisyUI **toggle**、多选一用 **radio**（两者形态必须一眼可分，别都塞 checkbox）；**按钮位**（工具条 / view bar / 图标切换）用 **swap**（隐藏 checkbox + 图标双态，省地方）—— 三者各司其职，别互串
- `pit.budget-compact` — 压缩 = **一个字节预算**（`budgetBytes`，UI 显示 KB，除固定开支外历史消息可占上限；`0`=清零，**且 0 时保底也不生效** —— 清零就是「全不要」）：缺省管道（##343 M1）= **保底最近 6 步 `clip: full`**（`exempt`，不计预算：只保下标不保字节治不了「留下的结果被裁成头尾」）+ 纵向优先级阶梯（`user > assistant结论 > assistant非结论 > tool-call > tool-result`，全局跨轮、同层新的先、call 与 result 同进退）计预算保留。**不是**「保留 N 轮」（横向会整轮陪葬前面重要的用户消息 —— 用户明确否决）
- `pit.plan-gate` — **plan 写闸只管 agent**（##362 M3a）：`history.allowAgentWrite` 缺省 `false`，只拦 `compact_plan` 工具那条路 —— CLI `compact plan set` / UI 编辑器是用户**自己的**显式操作，若也拦就没人能开闸了。两条实测坑：① 改 `saveKeepConfig` 时**必须保留 `history` 的其余字段**（整包换成 `{ keep }` 等于顺手把闸关掉 ⇒ agent 写一次就永久失去权限）；② 闸关时工具**返回拒绝文本而不抛错**（抛错会被当成工具失败、污染轮次信号，模型看不出"是没权限"），而**非法 plan 要抛**（那是调用方写错，该看到错在哪）—— 两者判据不同向，别互相抄
- `pit.config-vs-history` — **配置 / 历史分离**（用户 2026-10-07）：投递口径 = **当前配置**（`$DIY_HOME/auto-compact.yaml` 的 `policy` **+ `history.keep[]`**，见 `find.compact`），**每次请求实时算** ⇒ 改预算/改管道**本轮即生效**；压缩账（`<key>.compact.jsonl`）只是**不可变快照**（历史页/回溯用），**不决定投递**（v3 起每行带当时整条 plan 原文 ⇒ 可回放）。⚠️ 别再让投递去读 `resolveBoundary`（旧边界机制已废：没压过就不生效，违反直觉）
- `pit.history-filter` — **历史 = 固定的消息集合**；一次压缩 = 用**某算法**对它定义的一个**过滤条件**。事件里的 `policy` 承载**算法**（`mode`，现役只有 `budget`）与该算法的**过滤器表达**；**换算法 = 加新分支 + 新 filter 形状**，别用一套结构硬套。旧「分代（generations）」**已删除**（连续轮边界表达不了预算的分散保留）
- `pit.ops-fold` — **会话历史读出来是折叠过的**（`compactOps`；对消费端透明：同一棵块树，只是逐 token 的 delta 碎片变成每块「`start` + 一次终值 `patch` + `stop`」，实测一次 74MB / 87.7 万 op 的会话 → 15.2MB / 1.76 万 op）。三条不可动摇的约束：① **无父块必须显式写 `parent: null`** —— 省字段（undefined）在 JSON 里会整条消失，重放时退回栈顶，于是“本就该是根的块”被前一棵未闭合子树认领；② `patch` 值未变不写也不碰 `touched`、`stop` 只在“未定稿 → 定稿”那一次碰 ⇒ 对同一份折叠流**重复 apply 无副作用**；③ 折叠流按**轮次递增**（DFS 顺序 = 轮次顺序）；**缓存判据在 main**（`foldedOps`）：按 `(task, start)` 分键，用「已消费字节 + 前 4KB 指纹」判续 fold（`consumed > size` 或指纹变即整份重建）。渲染端是**按段**前缀守卫（`mergeWindow`）：末段轮次序列是新窗口前缀时**增量**并入，否则整段重置（**不是**「整份重建」）
- `pit.chat-reload` — **轮末收尾重放必须走「幂等并入」，不许重建**（`localChatStore.mergeWindow`）：旧实现每轮都 `new BlockStore()` 全量 fold → `toForest` 的身份缓存（TreeCache）整片失效 → Solid 的 `<For>` 把**每一轮**都销毁重建（含全量 Markdown re-parse）—— 这正是大会话“每次轮末 GC 风暴”的根因。折叠流幂等，再喂一遍即可，未变的轮次引用不变（实测第 1 轮 DOM 节点跨轮仍是同一对象）。大会话另有一层见 `pit.chat-virtual`：DOM 里只挂视口附近若干轮（离屏轮**不在 DOM**，不是靠 `content-visibility` 跳过绘制）
- `pit.chat-virtual` — **滚出视口的轮不挂 DOM**（##301；`lib/chat-virtual.ts` + `LocalChatPage` 的 `VirtRow`）：`content-visibility: auto` 只跳过离屏子树的布局与绘制，**DOM 与组件状态照旧**（48 轮实测 1441 个节点全体在树里）⇒ 要真降下来必须把远端轮摘掉。几何 = 每行**绝对定位**、顶边取**账面高度前缀和**（行间距由账给，不用 `space-y-*`：spacer 与相邻行的间距要另推一遍账，边界必差一个 gap）。三条硬约束：① **位置补偿只此一处** —— 任何"行顶边会变"的因（测量修正 / 前插补段 / 重置）都由同一个监听布局的 effect 按「视口锚点」纠正；`applyHeights` 与 `loadOlderInto` 各算一遍就是重复补偿（实测一次上滚多推 605px）；② **锚点锚在"块"上、不锚在像素上**（`pickAnchorIn`/`applyAnchor`）；程序化滚动**只走 `writeScrollTop`** —— 它写元素 + 同步 `scrollTop` 信号（虚拟窗口由信号驱动，只写元素则窗口还按旧位置挂行、锚点块不在 DOM）并记下写入值 `progWriteTop`，让紧随的 scroll 事件**不重取锚点**；分辨"用户在滚"归 `anchorTick` 的 `lastSt` latch（≤1px 容差，见 `pit.chat` 的 #331 条）；③ 高度估算的**唯一出口**是 `HeightLedger`（CSS 里不再留 `contain-intrinsic-size` —— 两处各估一次必然漂移），未渲染轮用已测均值、实测过的行**永久保留**（卸载不清账，滚回来位置才稳）
- `pit.md-reconcile` — **MarkdownView（`renderer_solid/components/MarkdownView.tsx`）必须走 solid-markdown 的 `reconcile` 策略，且 `pre` 里取代码正文/语言必须用访问器现读**。两个都是硬约束，破一个就有肉眼可见的 bug：① 用 `memo`（库的缺省）时每帧给出全新 hast 树，`<For>` 按引用比对 ⇒ **每帧把整棵子树拆了重建** —— 块内 `overflow` 容器的 scrollLeft 归零、拖出的选区被清空（用户看到的「拖到长行右侧又被拉回起点」「流式中选不中、copy 不了」）；② `reconcile` 按位置合并、节点对象**就地更新且身份不变** ⇒ 组件函数体只跑一次，`const n = props.node.children.find(...)` 这种读法会停在第一帧（表现为流式代码块只显示开头一段）。同理 `components/CodeBlock.tsx` 的两态（未定稿纯文本 / 定稿 Shiki）**共用一个恒常滚动外壳**：各带一个滚动容器的话，定稿那次切换等于把容器换掉，滚动位置照样丢。回归 `tests/cli.intent.ui-chat-render.test.ts`（桩上游逐 delta 推，判据是「同一个元素对象 + 滚动位置还在 + 选区还在」）

- `pit.flow-thread` — **讨论线程（##342）锚点 = 一条真打回边的一次穿越**：`{from: 打回前位置, to: 落点节点, seq: **落点那次驻留**的 Visit.seq}`（一次 bounce 恰创生一次驻留 ⇒ 三元组唯一；**同节点二次打回靠 `seq` 不串台**，##320 P1-1 的同一教训）；文本 id `from->to#seq`（`--thread` 参数 / UI 的 `data-flow-thread` / `flow-model.ts::threadIdOfVisit` 三方逐字一致，有单测钉）。三条立场：① **旁注**（`rule.core-log`）：`threads.jsonl` 不进 `state.json` / 不产生 `path.jsonl` 增量 / **删了不影响**推进与对账（线程结构仍从折线推得出来，只是发言没了），坏行**跳过并计数**（`flow show` 的 `FlowView.threadError` 错误位 + `flow thread list` 的 `skipped`，对照 ##337 P2-B，**绝不拖垮领域读**）；② **不造数据**：`postThread` 写前验「折线上确有这次 bounce 驻留」（`flow-thread.ts::requireRealBounce`），假锚点即拒；读侧对折线上查无的旧发言标 `real: false` 亮出来（坏数据不藏）；③ **三出口**：(a) 撤销打回 = **现有合法边**（dev 定义 `implement --next--> review` 就是那条，**不动内核**）(b) `--type resolved` (c) `--type escalate`（`actor: human` 的发言；领域侧落点 = 走到 `actor:human` 节点如 `approve`）—— 状态由**最后一条状态发言**决定。另两条别踩：④ **「不写空发言」闸门只有一处真源** `flow-store.ts::requirePostText`（`postThread` 与 `appendBounceOpinion` 共用）—— 驱动环的结论行**合法地可以只写「结论：打回」**（`reason: ""`）⇒ 闸门装在 `appendBounceOpinion` 里，驱动环已有 catch 故自动降级为**不写 + warn**（审计照旧记 `打回`：审计与讨论口径不同是对的，往留痕里凑一句评审没说过的话 = 造数据）；⑤ **出口 (a) 撤销打回在讨论视图上无留痕**（走既有合法边 ⇒ 不写讨论流 ⇒ 线程 `status` 停在 `open`）：**接受现状** —— 折线本身即留痕（多一次 `next` 驻留），不给「撤销」开第二处写入语义（避免写入路径分叉），留待 ##325 隐私/权限定案时一并看。UI 讨论区本轮**只读**（可见性/留痕是本任务交付，发放入口只在 CLI；「谁能发言」属 ##325，未定前不钉进 UI）
- `pit.flow-driver` — **驱动环（`services/flow-runner.ts`）判据只读状态**：每步重新 `flow show`（不靠内存进度）⇒ 幂等、可中断、续跑不重复消费；`rule.core-log` 的落点 = 帧与 `events.jsonl` **只作观察**，删了不影响运行（位置/折线/终态全在 `flow/state.json`）。五条别改错：① 分类**顺序**是 `human` → `system` → `agent`（「该谁拍板」优先于「守卫可不可观测」—— 反过来的话 `actor:human` + 可观测守卫会被**自推**，审批点就没了）；② **替用户起轮次前先问 `LocalAgentManager.busy(uri)`**（`chat()` 对忙会话**不拒绝、只排队** ⇒ 不问就会把节点提示词排进**用户自己的会话**、还收不到正文），忙 ⇒ 停因 **`session-busy`**、不碰队列不碰状态；中断时**只停自己起的那一轮**（归属判据 = 收到**自己的** `start kind:"turn"`，排队回执的 `meta.source === "queue"` 描述的是**别人**的轮次）—— ##305 拍板「消费端断开不掐轮次」，所以这句得自己补，不然 `flow run` 会卡在 `await` 上、轮次还烧 token；③ 打回判据是**末行明文约定**（`结论：通过` / `结论：打回（原因…）`，只在当前节点**真有 bounce 出边**时生效，读不到按通过）—— 可复核优先于猜语义；④ 结论**落袋失败不挡这一轮**（试译抛，如纯 JSON 对象落进 diff 节点；产物是派生数据、`rule.domain-first`），原因随 `turn` 帧的 `artifactError` **亮出**（不静默）；⑤ 本版三个限制：`next`/`bounce` 出边各取**第一条**（内核允许多条 + `when`，本版不挑）、**命令期不可停**（`stepFlow`/`collectFacts` 不接 `signal`，`exec` 自带 10 分钟上限）、`flow run` **退出码恒 0**（停因在帧里 —— 别拿退出码当判据）
- `pit.ownership` — 任务目录内 `AGENTS.md` 面向用户可编辑，`.diy/**` 系统独占（仅 main 经 RPC 写）；路径单一出口 `src/main/core/state.ts` 的 `taskSystemDir(uri)`
