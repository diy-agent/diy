# 上下文树页（ctxlab）约定表

> 本文件从 `pkgs.ts/diy-app/AGENTS.md` 移出：`AGENTS.md` 会经 `chainOf` 注入 system 提示词，
> 受 64KB 系统预算约束（`SYSTEM_BUDGET_CAP_BYTES`），长文放这里，AGENTS.md 只留指针。

| 关注点 | 位置 / 约定 |
|--------|-------------|
| 领域模型（冻结契约） | `src/shared/context/types.ts`：事实（snapshot/replace/patch/remove）→ 树（值树 + 渲染声明 + places/placement + wireVersion）→ 投影（system 全量 / runtime 增量）。**两个 hash 别混用**：`valueHash`（原始值）/ `renderedHash`（渲染出来的文本，模板没引用到的值变了它不变） |
| ⭐ 投递构造（真发与预览**唯一入口**） | `delivery.ts` 的 `buildDelivery(globals, systemPlaces)`：system＝`help`（zod 派生的结构说明）+ 稳定项（进 `streamText` 的 system 参数）；runtime＝易变项（作为**尾部 user 消息**，插在本轮输入之前，**不进块树/llm 历史** → 每轮现拼、不会累积）。`runTurn` 与上下文树页调的是**同一个函数**，所以"预览看到的字节"就是"发出去的字节"（`tests/core/context-delivery.test.ts` 守这条契约）。划分策略（`PLACE_CANDIDATES` / `defaultSystemPlaces`）也住这里 |
| ⭐ 行为契约节点（identity / rules / guard） | 由 `prompt-registry` 的 `assembleGlobals` **渲染模版节**得到（`DELIVERED_SECTIONS`：`identity.md` / `rules.md` / `_guard.md`，草稿 > 项目覆盖 > 内置），作为 globals 的顶层键进树。**为什么必须投**：这三节此前完全不在投递里 → 真发丢掉人物行为指令、行为规范与保命契约（209 review P0-1 实测全 false）；范围也回到 144「模版即节点」的方向。**注意**：投的是**渲染结果**（含身份行与 `{{persona.instructions}}`），不是 `persona` 值 —— 单列 `persona` 会把指令投两遍（一条值、一条节），身份行还仍旧缺席 |
| ⭐ usage 账本（收益指标） | `src/main/services/turn-usage.ts`：`in` / `out` / `cached` / `total`，`cached` = `usage.inputTokenDetails.cacheReadTokens`（**不是** providerMetadata：zen/go 实测它恒为空对象 `{"zen-go":{}}`）。UI 在轮次页脚显示 `⇄cached`；审计行 `usage=<in>/<out> cached=<n>`。这是 ##140 的验收指标、也是"划分到底省了多少"的唯一硬证据 |
| ⭐ 划分规则（真源） | **哪些变量进 system** 是 `$DIY_HOME/context.yaml`（不是页面本地偏好）。真发（`runTurn` → `loadSystemPlaces`）与页面读**同一份** —— 存 localStorage 的写法会让"页面改完预览变了、真发却不理"（界面说谎，实测踩到）。契约与净化在 `shared/context/config.ts`（`sanitizeSystemPlaces`：丢非法路径 / 丢互为祖先后代 / 去重 / 空则回落推荐名单，**返回 dropped 让调用方出声**）；文件 I/O 在 `main/core/context-config.ts`（缺失/坏 → 推荐名单 + warn；原子写 + 说明头）。RPC：`context config` / `context setConfig`；页面 ⇄ 写回真源，**下一轮真发**生效 |
| 真发快照（step） | `local-agent` 每轮真发 append 一条 `$DIY_HOME/local/<uri 路径>/<key>/steps.jsonl`（##379 分层；旧平铺 `<key>.steps.jsonl` 读侧兜底）（`DeliveryStepRecord`：值 hash 表 + 两份全文 + 名单 + wire 版本）；CLI `diy context steps <uri> [--limit N] [--diff]` 读出摘要 + 相邻 diff（**diff 在 main 侧算完**，默认只下发统计 —— 两份 system 各几十 KB，全文下发不可行）。**不塞 raw.jsonl**：那是旁路观测（不参与 UI/状态恢复），这份是投递事实。UI 的 step/diff 只用这份（早期那个 `history.ts` 页面轮询重算版已删 —— `d9917c9`） |
| 读写与校验 | `tree.ts`（嵌套 JSON 值树 + 不可变写入 + places 两两不可嵌套）、`reducer.ts`（applyFact 一律不静默合并：baseHash 不匹配即拒绝并要求 rebaseline）、`projection.ts`（内容未变不发 / 全消失发显式 clear / 版本或 placement 变化发 snapshot） |
| 纯 YAML 渲染 | `render.ts`：**自实现产出器**（不引 js-yaml 输出侧）——输出逐字节可预测（golden 拿它当基准）、shared/ 零 node 依赖；空对象/空数组输出 `{}` / `[]`（与"没有这个值"区分）；`renderPathsTraced` 的**行号映射与文本同出一次产出**（选中联动定位必须同源，否则指错行比不高亮更糟） |
| 块标量（多行文本落法） | ⚠️ 三条实测踩坑（都会让整份 YAML 解析失败或悄悄改内容，用例见 `tests/core/context-tree.test.ts` 的「块标量的保真」）：① **缩进指示符**：内容首行有前导空格时必须写 `\|2` —— 自动判定会把首行缩进当块缩进，于是后续浅行掉出块（`wc -l` 的 `   352 …` 让 338 条历史的请求预览崩在 509 行），或整段公共缩进被吞掉（源码类工具输出）；② **chomping**：原值尾换行 0 个时必须 `\|-`（strip），否则回读凭空多一个 `\n`；③ **控制字符**（终端 ANSI 色码）块标量表达不了 → 退回双引号转义标量（`JSON.stringify` 转义是 YAML 双引号转义的子集）。尾换行 ≥2 个同走转义标量。**判据是内容自身的前导空格，不是渲染后的行缩进** |
| ⭐ 信封（wire 的形态，##310 六轮） | `envelope.ts`：**一条消息 = 一份 YAML 信封**。system 参数 = `help:` + `system:`；尾部 user = **一份尾部信封**（`tailEnvelope`）= `runtime:`（每轮首步**全量**）+ `user: {message}`（**自己合成一份** —— 相邻 user 必被 `normalizeUserRuns` 合并，合成才能保证是合法 YAML）；轮中途 runtime 变 → **追加一条只含 `runtimeDiff:` 的消息**（值 = 该单元**变更后的当前值**；空则**不注入**，不砸前缀缓存）。`help` **只能由 zod 派生**（`describeSchema` + `pruneSchemaDoc` 按该容器**实际投递的 path** 裁剪 → 不会宣称 system 里有 skills），一小段固定话术 `ENVELOPE_ABOUT` 兜住总逻辑。**值节点里禁解释性字段**（`about`/`source`/`retrieve`/`legend`/`locate`/`body`）—— 解释一律上移 `help`（`historyIndex` 节点即因此删除）。旧的**手写说明头 `guide.ts` 已删**（它宣称 identity/rules/guard 进 system，而真源是 `$DIY_HOME/context.yaml` 的 `systemPlaces`）。⚠️ **自动生成的段一律自占一个顶层键**：注记曾作为一条普通 user 消息插在历史前，被 `normalizeUserRuns` 并进保留首条 user 的正文 → `user.message` = 「history 索引 + 用户原话」一坨，模型把它当成任务内容去查（tasks/5 实测多烧 3 次 bash、5.6 万 prompt token 就为答一个字）→ 改为 `history:` 与 runtime/user **平级**（`HistoryDelivery.note` 由 `buildHistory` 单独给出）。**位置（##421）**：注记自占一条 user 消息、挂在**历史首条之前**（system 之后）——用户原话「放最后一个，完全被淹没了」；故 `normalizeUserRuns` **不合并**信封形态的消息（判据 `envelope.ts::isEnvelopeText`），否则又会被并回相邻 user 正文。注记**只在真丢了消息时**出现（`selectHistoryByBudget` 无 gap ⇒ 空串），`keptBytes` 扣掉本轮 user 那一行（它作为 `user.message` 单独投递）；`runtime:` **保持尾部**（##421 裁：挪到前面会让整个历史每轮按 cache miss 计费）。`ENVELOPE_ABOUT` 另加一条固定话术：**历史压缩不影响变量树**（system / runtime 两段每次全量当前值）→ 别为「某个变量现在是多少」去额外查询。**摘要素 `summary:` 同法**（##310 九轮）：摘要此前也作为一条普通 user 消息前置 → 被并进保留首条 user 的正文（同坑），故改由 `renderSummaryPart` 拼进尾部信封（`withSummary` 已删、`SummarySchema` 落 `help.summary`）。⚠️ **顶层键集不进 `WIRE_ENCODING`**（加 `history` / `summary` 只改「给模型看的编排」，**不影响业务**：原子单元 hash 与投递值都没变）→ `WIRE_VERSION` 保持不变，免得存量 step 记录集体判「不可比」；真该动版本的只有 `WIRE_ENCODING` 里那些语义（投递形态 / hash 口径 / 渲染格式），见 `envelope.ts::ENVELOPE_ABOUT` 头注 |
| 页面数据 | `preview.ts`：真实 globals（`assembleGlobals` 的产物，不是示范数据）+ system 名单 → 树/规则/两份投递/请求体；`PLACE_CANDIDATES` 只声明 system 名单，其余自动 runtime（不是两套表）。**候选拆到子字段**（`task.title` 稳定 vs `task.body` 易变）——按第一层粗暴划分会让易变内容污染 system 缓存 |
| 请求预览（**只剩提示词页 lab 用**） | `request.ts`：**整份请求体渲染为一份大 YAML**（树形文本编辑器形态）。ctxlab 的「请求预览」view 已删（有真发请求了）—— 现在只有**提示词页**（模版线）用它，且那里的 `requestNote` 明写「这是模版线、不是会发出去的东西」。`splitGuide` 的精确切分随 `guide.ts` 一起删了，只剩「第一个顶层键之前算前后缀」的启发式兜底 |
| 页面与 view | `ContextLabPage.tsx` + registry 的 `ctxlab.*`：**两列**（左=变更历史/变更统计/结构树，中=变量树变更/system diff/runtime diff/该步实际请求）。**每个 view 都有一条 `<>`**（就地切该 view 的**原始数据**，再点切回；说明贴 view 顶的 **info bar**（`View` 的 `rawInfo`），不掺进正文；两侧 diff 的 `<>` 是**真发字节**：system → `steps.jsonl` 的 `systemText` 全文；runtime → 该步**实际发出去的末条 user 消息**，取自流量日志，查不到才退回组装产物并标注）。块折叠态走 `Caches.diy_ctxlab_fold`，CLI：`ui view expand ctx.<history\|stats\|structure\|vardiff\|sysdiff\|rtdiff\|stepsess> open\|closed`。**已删的 view**：请求预览、变更详情（有真发请求了，仿真不留） |
| 选中联动 | 点结构树一行 → 「变量树变更」里对应节点高亮（行号由渲染同源收集、内嵌块无需换算） |
| ⭐ 变更历史（**表格**） | 左栏「变更历史（真发轮次）」**读 `context changelog`**：表格三列 `轮次 \| 步 \| 实际请求` —— 轮 = `#M`（按 `turnId` join 投递快照得到的轮序，**取不到画 `—`**；⚠️ 不能用 changelog 文件内行号：老任务升级后两份日志不等长，##310 review 意见 1）、步 = `ref.step`（该轮内第几次真发）、实际请求 = **超链接** → 弹**流量抽屉**（与对话页报错后「查看实际请求」同一个抽屉；先查一次拿到 `reqId/traceId` 再开，否则定位会退化成「最近一次失败」）。**只有「步」这一层**：不树形、不列变化字段（那是「变量树变更」块的事）、不加「变更数」列（用户 2026-10-15 拍板）。行的 `title` 里带 system 是否重建 / 由谁引起（应用 `sysCauses` + **该轮快照**的 `systemPlaces`，RV-02）+ 缓存率 + 金额。点一行 = 选中这条记录（`pickedSeq`，驱动「变量树变更」与「该步实际请求」）—— 从前的「只有 `turnIndex` 才算选中」会让取不到轮序的行点了没反应 |
| 变更日志（落盘） | `main/core/context-changelog.ts` + `shared/context/changelog.ts`：**每步**真发 append 一条 `$DIY_HOME/local/<uri 路径>/<key>/changelog.jsonl`（##379 分层）（`CtxLogEntry`：`seq` + `type`(`baseline`/`changed`) + `ref{turnId,stepId,step}` + `data`）。`changed` 的 `data.changes[]` = `{type,path,data:{before,after,truncated?}}`（**before/after 自带** → 读侧不回放）。**有变才写**（无变的步不落盘）；**每段会话的起点 = 一条 `baseline`（整棵树）**，可有多条（清零 / `diy context rebaseline` 各另起一段）。写起点的判据 = 「文件里还没有**二版**记录」**或**「有重置标记」—— 老文件里全是老格式时也补起点（否则 UI 永远停在降级视图）。**进程重启不算会话边界**（对话从盘上重建、继续），重启不写新起点；`agent clear`（会话清零）**不删 changelog**（它是跨会话的审计时间线），只置起点标记。**变更单位 = 原子单元**（`PLACE_CANDIDATES`，数组不下钻：`chain` 整体一条，禁 `chain.0.content`）。`seq` = 文件内序号（0-based，重启从末行 +1）。分工：steps 存全文（大、可清）、changelog 存变更 + 一行摘要（小、可长期留） | ⚠️ **比较基准 = 内存游标**（`LocalAgentManager.ctxSnap`，**跨轮**）：用轮首值当基准就只能看见「轮内变化」，跨轮变化（改完正文再来问）会永远漏掉；进程重启后游标为空 → **从盘上播种**（`seedCtxSnap`：`valueHashes` 取 steps 末条 + 值树由 `foldCtxTree` 从 changelog 的 `baseline` 起重放，注意重放是**单元级**、长值只有摘要）；播不出来（老任务没 baseline / 从没真发过）才退回轮首基准 ⇒ **少报不错报** |
| ⭐ ref 的两段来源 | 变更日志本身**不含**轮次 ref —— 由 main 在 `context changelog` 里按 `turnId` join 两份：① 投递快照（当轮 `systemPlaces` + 两份容器是否变）；② 用量账本 `<key>.usage.jsonl`（缓存率 = `cacheRead/inputTotal`、金额）。**任一段不可得即 null**（UI 不画徽章）—— 快照会被清、老账本没字段，编个数比不给更坏 |
| ⭐ 变更历史的重置入口 | `diy context rebaseline <uri>`（RPC `context rebaseline`）→ `LocalAgentManager.rebaselinePending`（**内存 Set**）置位，该任务**下一次真发**落一条新 baseline。**临时**入口：会话注册表/关停启动机制落地后，置位的两处（`clear` / 本命令）换成「会话启动」一处即可，命令留作调试口 |
| 变更历史的降级路径 | ① 老格式 changelog（一版 `{ts,turnId,ops}`）→ `foldCtxLog` **回放兼容**；② 该任务**没有** changelog → main 用 `steps.jsonl` 的 `valueHashes` 差**折算**（`source: "derived"`）：只有 path 粒度、没有值预览。二版新格式**不回放**（before/after 自带）。UI 写明「降级视图」。有日志即以日志为准 |
| ⭐ 归属与归因（纯函数） | `src/shared/context/attribution.ts`：`attributionOf`（一个 path 落在哪个投递单元 —— 三态 unit/container/none）、`sysCauses`（system 重建由谁引起）、`foldStatRows`（统计表行粒度）、`unitsFromRules` / `unitsFromSystemPlaces`（划分 → 单元 map）。**单元名单只认 `delivery.ts` 的 `unitPathsOf`**（候选 ∪ 名单 − 互斥候选）—— 与真发同一份，另算一份必漂移（RV-14：手填候选外单元被丢、祖先级单元造出幽灵子单元） |
| ⚠️ 两处归属口径**有意不同** | 「变更统计」表的归属列与中间容器折叠、结构树的 ⇄ 开关 = **页面当前划分**（用户眼前这把刀，改划分即重算）；「变更历史（真发轮次）」的 sys 徽章 = **该轮快照**的 `systemPlaces`（历史不该被当前划分改写，RV-02）。统计是**项目累计跨任务**聚合，每条记录只存 `changed`、不存当轮划分，按快照算归属要把记录反查回对应任务步骤（跨文件、快照可被裁）—— 成本远超收益，故取标注口径（RV-09）。UI 上两处都必须写明 |
| 变更统计的分母 | `stats.ts` 的 `summarizeStats`：`turns` = 该范围**真发轮数**（含没变的轮）；`rate = changes / turns`。**首轮不算变化**（没有上一轮就没有"变化"）—— 写入侧 `statFromStep` 给 `[]`，存量数据由读侧 `dropBaselineChanges` 抹平（必须在 filter/slice **之前**调，RV-15：否则每任务首轮把 41 个 path 全记成变化，从不变过的 `diy`/`guard`/`rules` 会显示成"变了 39 次 · 7.2%"） |
