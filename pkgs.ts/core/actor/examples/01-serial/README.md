# 01 — 不排队会丢东西

**这一节只讲一件事：并发调用同一个状态，没有队列就会丢更新。别的都别记。**

## 跑

```bash
./sha.sh e01
```

## 输出

```
不用 actor，连点三次 → 1（应该是 3）
用 actor，连点三次 → 1, 2, 3（每个调用拿到自己那一次的结果）
最后读一次 → 3
两个 actor 同时跑 → slow + fast，耗时 51ms（≈50，不是 100）
第一条炸了 → boom
第二条照跑 → still alive
```

## 为什么

`unsafeInc` 干的事是「读 → await → 写」：

```ts
const value = counter;
await sleep(10); // ← 真实代码里这里是 fetch / 文件 / LLM
counter = value + 1;
```

三个调用同时进来，在 `await` 那 10ms 里都读到了同一个 `value`，于是三次写进去的是同一个数。

`actor` 把三个调用排成一条链，`await` 期间没人能插进来。

## 四个断言

| 断言                               | 看哪一行输出                           |
| ---------------------------------- | -------------------------------------- |
| 不排队 → 丢两次                    | `→ 1`                                  |
| 排队 → 一个不少                    | `→ 1, 2, 3`                            |
| 每个调用拿回**自己**那次的结果     | `safe.inc()` 分别 resolve 成 1 / 2 / 3 |
| 粒度是「一个 actor」，不是一个进程 | 两个 actor 并发耗时 ≈50ms 而不是 100   |

最后一段还说明：**一条命令失败不该卡死后面全部**。`fail()` 抛了，`ok()` 照样跑 —— 因为链尾用 `.then(fn, fn)`，前一个 reject 也继续往下走。

## 常见误解

- ❌「加锁就够了」—— 锁只保护临界区。「读历史 → 调 LLM → 写回复」这个临界区跨了很多个 `await`，锁住它等于把整个 actor 串起来，那就已经是队列了。
- ❌「actor 是并发原语」—— 它**不**创造并发。它的作用相反：把并发收窄成顺序。
