## app-variant

**`lab`/`staging` 是运行空间，不是构建目标**：产物一份（`build/app/`，tsc+esbuild，与变体无关）；变体只决定 `DIY_ENV`、CDP/副屏、数据根。`staging` = prod 构建产物 + 隔离数据根，**`prod` 一词只留给真正的生产**（`~/.diy`，由全局 `diy` 起）。启动实例一律 `./sha.sh run <launch> [--slot N]`；`./sha.sh lab` 已弃用（转发到 `run lab`）。判据：拉完代码看到旧界面 ⇒ 先怀疑 `build/app` 产物过期，不是代码没合。

## by-type

**先判类型再选打法，不要所有任务一套**：

| 类型 | 打法 | 明确不要做 |
|---|---|---|
| UI / 视觉 / 交互 | `./sha.sh lab` 起实例，人眼 + **少量** CDP 抽样；可观测性差或要主观判断 → 叫醒用户（见 `dev.wake-user`） | 几十轮 CDP 逐像素猜、为一行样式硬啃 |
| 纯逻辑 / 内核 / CLI | 先写判据（纯函数 + 单测）再实现；意图测试收口 | 起 GUI 验证 |
| 数据修复 | 备份 → 改 → 复扫 + 逐字比对 | 跑一次就宣布修好 |
| 文档 / 配置 | `./sha.sh check` + 索引护栏 | 额外造测试 |
| 性能 | **先量再动**：给出基线数字再改，改完用同一个测量口径复测 | 凭感觉「应该更快了」 |

## for-test-persona

真 LLM 实验**只用 `for-test` 人物**（`~/.diy/personas.yaml` 的 `persona/9`）；该人物**不得用于自动化测试**（自动化测试走隔离 home + 种子，**绝不**依赖 `~/.diy` 真配置）

## lab-model

**lab 数据根（仓库根 `build/<variant>/home`）的真配置由 `./sha.sh sync` 自动同步**：把 `~/.diy/` 的 `model.yaml` / `context.yaml` / `personas.yaml` / `providers.custom.yaml` 逐字投影进去（变体随 `DIY_VARIANT`，缺省 lab；`DIY_SYNC_HOME=0` 关）—— **不再手抄**（手抄极易漏 `context.yaml` = 投递划分真源，漏了测到的划分是种子那份）；seed 只种示例数据（示例项目/任务 + 占位人物）

## lab-scope

`lab`（唯一 GUI 启动器，原 `preview` 已删，##381）**只用于探测性开发**（人看效果 / 手工验一条真请求 / 临时实验）；**不要**用它做自动化测试、压测、批量跑（那些走 `test` variant 与既有测试入口）

## long-task

**长命令不靠 `sleep` 轮询**：bash 工具**缺省不设超时**（##454 用户 2026-10-29 裁决：默认不超时，显式给 `timeout` 才限时），命令跑多久就等多久；要限时/防挂就自己给 `timeout`。仍超长就 `nohup … &` **一次**，然后做别的事/汇报，用一次 `tail` 取增量 —— 绝不用「`sleep 30` → 看一眼 → 再 `sleep 30`」把一步工作切成十步（每步都是一次完整请求）。

## model-cheap

实验一律用**免费或最便宜**的模型（缺省先挑 `diy/AGENTS.md` 的 `model.free` 可用项，退 `mimo-v2.5`；`mimo-v2.6-flash` 自 2026-10-17 起**不作缺省** —— 上游返回 `[model_coming_soon]`）；贵模型只在用户明确许可下、一次一条用例

## model-unavailable

模型不可用（上游 `model_coming_soon` / id 不认识 404 / 认证 401·403 / 配额 429）→ **停工 + 通知**，**不换模型硬试**；实验实例页顶出 bar（判据 `apps/diy-app/src/shared/model-unavailable.ts`；上游 5xx 与超时**不算**，那是另一类问题）

## test-fixture

**意图测试里的「夹具」不许写成 `it`**（##433 / ##434）。判据一句话：这条用例单独跑（`vitest run <file> -t '<名>'`）时还有意义吗？没有 ⇒ 它就不是用例，是夹具。

- 夹具（造数据 / 建任务 / 开页面 / 置模块级变量）一律进 `beforeAll`；要被每条用例重置的才 `beforeEach`。
- **作用域按「谁用它」定**：只本 describe 用 ⇒ describe 级 hook；跨 describe 共用（典型：基础 `uri`）⇒ **文件级** hook —— describe 级 hook 只在该 describe 有用例被选中时才执行，单跑别的 describe 时它不跑，夹具仍缺席。
- 被夹具预置的状态若又被某条用例「再推一步」（例：先点成原文态、再点回渲染态），那条用例要**自己补齐前置**（`if (状态不对) 补一步`），否则 `-t` 单跑仍是假红；#433 的「账本空时自己跑一次 `compact run`」同此。

为什么值钱：`-t` 是排查单条用例的唯一手段。夹具带序时依赖 ⇒ 任何人拿 `-t` 定位，先看到的是「环境坏了」而不是「用例过了/没过」，每次都得先花一轮证伪（##433 的 `-e3b0c44298fc` 假目录就是这么来的）。

（见 42199e1c:pkgs.ts/diy-app/tests/cli.intent.ui-compact.test.ts:187）

## verify-budget

**验证预算按改动面走，不按习惯走**：改一个文件只跑受影响的 1~3 个测试文件；全量套件（`./sha.sh check` / `test-unit` / 全量 intent）**只在收工前跑一次**。禁止「改一行 → 全量」循环 —— 一次全量 30~120s（还可能触发 bash 超时），循环 N 次等于把 N 次完整请求赔进去。红灯即停（先修再看），但回报必须如实写「跑到第一个失败为止：N files / M passed / 其余未跑」，不许报成全量通过。

## wake-user

**agent 的可观测性有上限，到了就喊人，不许硬啃**。判据：需要人看一眼（视觉/交互效果）/ 需要人做决定（方案取舍）/ 卡住超过一次尝试。喊法 = 在会话里写三句话（**要你做什么 / 现在卡在哪 / 我试过什么**），然后**结束本轮** —— 不要空转等，也不要指望用户盯着日志看。
