## doc-format

每条一行：`- \`<域>.<对象>.<方面>\` — 值`。key 全链唯一，同一事实只在最该负责的那层写一次（深层同名 key = 覆盖）。值超过一行说明它是细节 → 删掉，改成指向路径。

## doc-fresh

**AGENTS.md 是代码的信息投影，不是知识库**。只写「去哪找 / 用什么 / 硬约束 / 反直觉的坑」，不写易变细节（字段清单、UI 文案、实现步骤）。**代码大改后对应层必须整篇重写**，而不是打补丁 —— 投影腐坏比没有投影更糟。

## doc-scope

分层职责：`~/AGENTS.md` 全局规则 · `~/git/AGENTS.md` 项目指针 · 项目 AGENTS.md 该项目事实 · 包 AGENTS.md 仅包内定位与坑。**下层不重复上层**。

## inherit

全局规则（skills 命名前缀、AGENTS.md 格式、工具偏好）见 `~/AGENTS.md`，本层不重复

## sketch-html

**给用户看 UI / 布局方案一律产出「单文件可交互 HTML」**（内联 CSS + 原生 JS，`open` 即看，能点着折叠 / 切状态 / 多版并排对比），不写 ASCII 或纯文本草图。多版对比渲染**同一份 DOM**、只换皮肤 —— 顺带就当「同构」的字面验证。

## specs

**各领域规范的索引总表在 `~/SPECS.md`**：正文仍住各层 AGENTS.md（分层加载不变），总表只做索引与查重；**新增 / 修改跨领域规范先查表去重**，`./sha.sh check` 的 `check-specs` 机械保证 key 不重复、指针不悬空。
