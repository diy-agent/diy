## core-log

**核心逻辑不依赖日志**：模块的领域状态自成真源、可独立序列化落盘；日志（事件流）降为**审计/统计**材料，可清可丢、丢了不影响运行；进程内的 Event 只是模块间进度通知的消息。横向模块关联靠**显式 ref**（如 `turnId`/`stepId`），不靠共享日志。**历史转变**：早期把日志当投影真源（ops → historyMessages），致模块逻辑被日志绑死、难进化 → **新 module 一律按新思路设计，旧模块不追溯**。代表：##310 / ##311(工作流特性专项)。

## discriminated-union

**判别联合 = `{ type, 公共字段…, data }`，自相似**：判别键默认 `type`（历史 `kind`/`op`/`mode`/`render` 不动），同级字段**所有分支共有**，分支私有数据一律进 `data`（用统一 `data` 而非 `<判别键>Data`，否则通用代码要拼字符串取载荷）。嵌套同构：子对象也是 `{ type, data }`。
**判据问未来，不问现在**：不问「它现在是不是判别键」，问「**取值会不会让对象需要额外字段**」。会（`mediaType`：png 要 encoding、mp4 要 codec）⇒ 嵌套；不会（`id`/`text`/`seq`）⇒ 可平铺。⚠️ 判成「值」是赌博 —— 某取值一旦长出私有字段，它事实上已是判别键而形式上没建，字段被平铺「凑合」，事后改造要动所有消费方。仓库里 `kind`/`op`/`mode`/`render` 并存就是「遇到新维度起个新名字」的产物：存量不主动追溯，但**改动已在动那个 interface 时顺手改掉**。
