## atomic-task

**任务是原子开发单元**：建任务的前提是它能**独立开发 + 独立 merge 回 main 且 main 仍可用（可编译、可验收）**。做不到（改动与别的任务共用同一处代码、merge 后 main 半截）即切分错了 → 要么重划边界，要么并成一个任务一次性成型。**先后顺序靠排序表达，不靠拆任务。**

## task-artifacts

**任务产物（工具 / demo / 文档等）落位**：**临时**的一律进系统临时目录（`/tmp`、`mktemp -d`），不落任务目录；**需长期参考**的进**任务目录** `$DIY_HOME/projects/<pid>/tasks/<tid>/gen/<类别>/`（`$DIY_HOME` = `~/.diy`；如 demo → `…/tasks/<tid>/gen/demo/<名>/`，**每个 demo 独占一目录**，别把多文件混作一堆 —— 一个目的常产多个文件）。⚠️ **是任务目录、不是 worktree 的 `./gen/`** —— agent 的 cwd = worktree，写相对路径 `./gen/` 会落进**产品仓**（禁止：产品仓只放产品资产，任务截图 / demo 不是）。**带时效**的（一版接一版，如 demo 迭代）目录名带「日期 + 序号 + 用途」；**长期事实**（不随时间变）**不加日期**。

## task-owner

**父任务 / 根任务是其子任务的 owner，自身不写码**。owner 只做四件事：**计划**（拆子任务 / 排序 / 定边界）、**review**（子任务交付）、**排查**（追根因、定位到代码）、**沟通**（回用户、派活）。要写码 → **开子任务派出去**。owner 的产物是**任务 body**（台账 / 计划 / 订正 / review 记录），不是 diff。

## task-ref

**引用任务一律写成 `##<号>(<标题>)`**（如 `##227(会话清零)`），完整 URI 同理补标题；不写裸编号 —— 人记不住数字号是干什么的。标题取任务当前标题的短名。

## task-root-logical

**逻辑根 ≠ 物理根**：任务树由 `parent` 字段表达，但**尚未打平** —— 有些任务物理上挂在**目录型容器**下（如 bug汇总 `##158(bug汇总)` → 归档 `##162(bug汇总归档（158 已修复项）)`；分配官 `##87(任务分配)`），**逻辑上仍是根任务**。判据看**职责不看挂点**：自成专项、养着子任务的就是逻辑根 → 按 `rule.task-owner` 办（不开发，只计划 / review / 排查 / 沟通）。临时安排，待树打平后自然消解。

## task-write

**任务文件头是权威**（##322）：读侧 `task show` / `getTask` / 上下文 `task.*` 就是 frontmatter 同一份（不必 `cat`）；写侧收到「整份文件」一律**剥头**，`--body` 只收内联正文（见路径样值即拒，##338）→ `docs/task-write-contract.md`（`--body-text` / `--body-file` / `--append-body*` 三选一、create 不剥头、##376 同族护栏）
