# 上下文树页（ctxlab）约定表

> 本文件从 `apps/diy-app/AGENTS.md` 移出：`AGENTS.md` 会经 `chainOf` 注入 system 提示词，
> 受 64KB 系统预算约束（`SYSTEM_BUDGET_CAP_BYTES`），长文放这里，AGENTS.md 只留指针。

| 关注点 | 位置 / 约定 |
|--------|-------------|
| 领域模型（冻结契约） | `src/shared/context/types.ts`：事实（snapshot/replace/patch/remove）→ 树（值树 + 渲染声明 + places/placement + wireVersion）→ 投影（system 全量 / runtime 增量）。**两个 hash 别混用**：`valueHash`（原始值）/ `renderedHash`（渲染出来的文本，模板没引用到的值变了它不变） |
| ⭐ 投递构造（真发与预览**唯一入口**） | `delivery.ts` 的 `buildDelivery(globals)`：产出信封全文（`help:` + `vars:`，一份全量）、纯数据段、值 hash 表与单元名单；变化由 `controlDeltaDelivery(tree, paths)` 现拼。`runTurn` 与上下文树页调的是**同一个函数**（`tests/core/context-delivery.test.ts` 守这条契约） |
| ⭐ 段首 system 快照（缓存命中的**第一块**） | `src/shared/context/segment-snapshot.ts`（纯函数）：跨轮/跨步**逐字复用**上一次真发落盘的 `systemText`，只在「无快照 / 压缩换段 / 老格式（没有顶格 `vars:`）」时重建。判据是 `/^vars:/m`（`vars: {}` 也算新格式 —— 逐行相等判据会把它误判成老格式 ⇒ 每轮重建 system、缓存全废）。变量树里 `self` 每步都变，所以**任何"把变量重算进 system"的写法都等于每步按全价重付**（##486 实测：390k 上下文一次冷启动 $0.056） |
| ⭐ 每步控制增量（变几个字段就发几个字段） | `src/shared/context/step-delta.ts` 的 `stepDeltaOf(prev, next, units)`：`changesOf` 找**变化的原子单元** → 按本步划分分 `system` / `runtime` 两段 → `controlDeltaDelivery` 渲染（值＝变更后的新值；单元消失＝`path: null`）。空串＝这一步什么都没变，调用方**不注入**（不加消息、不加字节）。`local-agent` 的 `sentOf`（跨轮，拼进本轮 user 信封）与 `prepareStep`（轮内，追加一条 user）共用它 —— 两处各写一份分流逻辑必然漂移。契约见 `tests/core/context-cache-delta.test.ts` |
| ⭐ 行为契约节点（identity / rules / guard） | 由 `prompt-registry` 的 `assembleGlobals` **渲染模版节**得到（`DELIVERED_SECTIONS`：`identity.md` / `rules.md` / `_guard.md`，草稿 > 项目覆盖 > 内置），作为 globals 的顶层键进树。**为什么必须投**：这三节此前完全不在投递里 → 真发丢掉人物行为指令、行为规范与保命契约（209 review P0-1 实测全 false）；范围也回到 144「模版即节点」的方向。**注意**：投的是**渲染结果**（含身份行与 `{{persona.instructions}}`），不是 `persona` 值 —— 单列 `persona` 会把指令投两遍（一条值、一条节），身份行还仍旧缺席 |
| ⭐ usage 账本（收益指标） | `src/main/services/turn-usage.ts`：`in` / `out` / `cached` / `total`，`cached` = `usage.inputTokenDetails.cacheReadTokens`（**不是** providerMetadata：zen/go 实测它恒为空对象 `{"zen-go":{}}`）。UI 在轮次页脚显示 `⇄cached`；审计行 `usage=<in>/<out> cached=<n>`。这是 ##140 的验收指标、也是"划分到底省了多少"的唯一硬证据 |
| ⭐ 变量树只有一份（##520） | 模型 wire 的信封 = `help:` + `vars:`（**一份全量**）。曾经「哪些变量进 system」的名单（`$DIY_HOME/context.yaml`）与 `system/runtime` 两容器**已整段删除**：前缀缓存靠**段首快照**（`local-agent` 的 `frozenSystemTextOf`），不靠挑选单元。旧文件不再被读、旧 RPC（`context config` / `setConfig`）不再存在 |
| 原子单元（增量粒度） | `delivery.ts::PLACE_CANDIDATES` 只是**单元名单**（哪些 path 各自成一条增量），不再有 `system: true/false`。拆子字段的理由不变：改正文不该把整段任务头重发；每个单元为什么单列写在 `reason` 字段（结构树表显示） |
| ⭐ 输入超长门禁（##426 B） | `shared/context/input-limit.ts`（纯函数）：`inputGate` 量**本条用户消息**——字符数（code point 口径）/ 估算 token（字节/4）/ 成本增量（按最后一步单价快照 × 非缓存输入价）/ 窗口占用。阈值 = `$DIY_HOME/input-limit.yaml` 的 `inputLimitChars`（缺省 `DEFAULT_INPUT_LIMIT_CHARS = 100_000`，`main/core/input-limit-config.ts::loadInputLimitChars`；##520 从 context.yaml 独立出来）。超限 → 对话页弹 `InputLimitDialog`；未超限**零打扰**。转文件 = RPC `agent.local.pasteToFile` |
| 真发快照（step） | `local-agent` 每轮真发 append 一条 `$DIY_HOME/local/<uri 路径>/<key>/steps.jsonl`（##379 分层；旧平铺读侧兜底）（`DeliveryStepRecord`：值 hash 表 + `places` + **一份 system 全文** + wire 版本；老快照的 `runtimeText` 读侧容忍、不参与新结论）；CLI `diy context steps <uri> [--limit N] [--diff]` 读出摘要 + 相邻 diff（**diff 在 main 侧算完**，默认只下发统计）。UI 的 step/diff 只用这份 |
| 读写与校验 | `tree.ts`（嵌套 JSON 值树 + 不可变写入 + places 两两不可嵌套）、`reducer.ts`（applyFact 一律不静默合并：baseHash 不匹配即拒绝并要求 rebaseline）、`projection.ts`（内容未变不发 / 全消失发显式 clear / 版本变化发 snapshot；增量按单元 `renderedHash` 逐条比） |
| 纯 YAML 渲染 | `render.ts`：**自实现产出器**（不引 js-yaml 输出侧）——输出逐字节可预测（golden 拿它当基准）、shared/ 零 node 依赖；空对象/空数组输出 `{}` / `[]`（与"没有这个值"区分）；`renderPathsTraced` 的**行号映射与文本同出一次产出**（选中联动定位必须同源，否则指错行比不高亮更糟） |
| 块标量（多行文本落法） | ⚠️ 三条实测踩坑（都会让整份 YAML 解析失败或悄悄改内容，用例见 `tests/core/context-tree.test.ts` 的「块标量的保真」）：① **缩进指示符**：内容首行有前导空格时必须写 `\|2` —— 自动判定会把首行缩进当块缩进，于是后续浅行掉出块（`wc -l` 的 `   352 …` 让 338 条历史的请求预览崩在 509 行），或整段公共缩进被吞掉（源码类工具输出）；② **chomping**：原值尾换行 0 个时必须 `\|-`（strip），否则回读凭空多一个 `\n`；③ **控制字符**（终端 ANSI 色码）块标量表达不了 → 退回双引号转义标量（`JSON.stringify` 转义是 YAML 双引号转义的子集）。尾换行 ≥2 个同走转义标量。**判据是内容自身的前导空格，不是渲染后的行缩进** |
| ⭐ 信封（wire 的形态，##310 六轮 / ##520） | `envelope.ts`：**一条消息 = 一份 YAML 信封**。system 参数 = `help:` + `vars:`（变量树全量）；尾部 user = 变量增量（`vars:` 一段）+ `notify:` / `chat:`。变量变了只把**变化的原子单元**摘出来追加一条 user 增量（空则**不注入**，不砸前缀缓存）。`help` **只能由 zod 派生**（`describeSchema`），一小段固定话术 `ENVELOPE_ABOUT` 兜住总逻辑。**值节点里禁解释性字段**（`about`/`source`/`retrieve`/`legend`/`locate`/`body`）—— 解释一律上移 `help`。⚠️ **自动生成的段一律自占一个顶层键**（否则会被 `normalizeUserRuns` 并进用户正文）。重放历史时剥掉控制段（`vars:`；legacy `system:` / `runtime:` / `runtimeDiff:` 一并剥），`from:` / `history:` / `summary:` 逐字保留 |
| 页面数据 | `preview.ts`：真实 globals（`assembleGlobals` 的产物）+ 单元名单 → 树/单元/信封全文/请求体。**候选拆到子字段**（`task.title` vs `task.body`）——按第一层粗暴划分会让「改正文」重发整段任务头 |
| 请求预览（**只剩提示词页 lab 用**） | `request.ts`：**整份请求体渲染为一份大 YAML**（树形文本编辑器形态）。ctxlab 的「请求预览」view 已删（有真发请求了）—— 现在只有**提示词页**（模版线）用它，且那里的 `requestNote` 明写「这是模版线、不是会发出去的东西」。`splitGuide` 的精确切分随 `guide.ts` 一起删了，只剩「第一个顶层键之前算前后缀」的启发式兜底 |
| 页面与 view | `ContextLabPage.tsx` + registry 的 `ctxlab.*`：**两列**（左=变更历史/变更统计/结构树，中=变量树变更/system diff/该步实际请求）。**每个 view 都有一条 `<>`**（就地切该 view 的原始数据；说明贴 view 顶 info bar）。块折叠 CLI：`ui view expand ctx.<history\|stats\|structure\|vardiff\|sysdiff\|stepsess> open\|closed`。**已删的 view**：请求预览、变更详情、**runtime diff**（##520 只有一份信封） |
| 选中联动 | 点结构树一行 → 「变量树变更」里对应节点高亮（行号由渲染同源收集、内嵌块无需换算） |
| ⭐ 变更历史（**表格**） | 左栏「变更历史（真发轮次）」**读 `context changelog`**：表格三列 `轮次 \| 步 \| 实际请求` —— 轮 = `#M`（按 `turnId` join 投递快照得到的轮序）、步 = `ref.step`、实际请求 = **超链接** → 弹**流量抽屉**（先查一次拿 `reqId/traceId` 再开）。**只有「步」这一层**。行的 `title` 里带 system 全文是否变（##520 起不再编「由谁引起」）+ 缓存率 + 金额 |
| 变更日志（落盘） | `main/core/context-changelog.ts` + `shared/context/changelog.ts`：**每步**真发 append 一条 `$DIY_HOME/local/<uri 路径>/<key>/changelog.jsonl`（##379 分层）（`CtxLogEntry`：`seq` + `type`(`baseline`/`changed`) + `ref{turnId,stepId,step}` + `data`）。`changed` 的 `data.changes[]` = `{type,path,data:{before,after,truncated?}}`（**before/after 自带** → 读侧不回放）。**有变才写**（无变的步不落盘）；**每段会话的起点 = 一条 `baseline`（整棵树）**，可有多条（清零 / `diy context rebaseline` 各另起一段）。写起点的判据 = 「文件里还没有**二版**记录」**或**「有重置标记」—— 老文件里全是老格式时也补起点（否则 UI 永远停在降级视图）。**进程重启不算会话边界**（对话从盘上重建、继续），重启不写新起点；`agent clear`（会话清零）**不删 changelog**（它是跨会话的审计时间线），只置起点标记。**变更单位 = 原子单元**（`PLACE_CANDIDATES`，数组不下钻：`chain` 整体一条，禁 `chain.0.content`）。`seq` = 文件内序号（0-based，重启从末行 +1）。分工：steps 存全文（大，体积治理见 ##410）、changelog 存变更 + 一行摘要（小、可长期留） | ⚠️ **比较基准 = 内存游标**（`LocalAgentManager.ctxSnap`，**跨轮**）：用轮首值当基准就只能看见「轮内变化」，跨轮变化（改完正文再来问）会永远漏掉；进程重启后游标为空 → **从盘上播种**（`seedCtxSnap`：`valueHashes` 取 steps 末条 + 值树由 `foldCtxTree` 从 changelog 的 `baseline` 起重放，注意重放是**单元级**、长值只有摘要）；播不出来（老任务没 baseline / 从没真发过）才退回轮首基准 ⇒ **少报不错报** |
| ⭐ ref 的两段来源 | 变更日志本身**不含**轮次 ref —— 由 main 在 `context changelog` 里按 `turnId` join 两份：① 投递快照（system 全文是否变）；② 用量账本 `usage.jsonl`（缓存率 / 金额）。**任一段不可得即 null**（UI 不画徽章） |
| ⭐ 变更历史的重置入口 | `diy context rebaseline <uri>`（RPC `context rebaseline`）→ `LocalAgentManager.rebaselinePending`（**内存 Set**）置位，该任务**下一次真发**落一条新 baseline。**临时**入口：会话注册表/关停启动机制落地后，置位的两处（`clear` / 本命令）换成「会话启动」一处即可，命令留作调试口 |
| 变更历史的降级路径 | ① 老格式 changelog（一版 `{ts,turnId,ops}`）→ `foldCtxLog` **回放兼容**；② 该任务**没有** changelog → main 用 `steps.jsonl` 的 `valueHashes` 差**折算**（`source: "derived"`）：只有 path 粒度、没有值预览。二版新格式**不回放**（before/after 自带）。UI 写明「降级视图」。有日志即以日志为准 |
| ⭐ 归属（纯函数） | `src/shared/context/attribution.ts`：`attributionOf`（一个 path 落在哪个投递单元 —— 三态 unit/container/none）、`foldStatRows`（统计表行粒度）、`unitsFromRules` / `allUnits`。单元名单只认 `delivery.ts` 的 `unitPaths()`（与真发同一份） |
| 归属口径 | 结构树与统计表都按**当前单元名单**（全量候选）算；##520 起没有「当轮 system 名单」这层，历史轮次的 sys 徽章只表示「该轮 system 全文变了」 |
| 变更统计的分母 | `stats.ts` 的 `summarizeStats`：`turns` = 该范围**真发轮数**（含没变的轮）；`rate = changes / turns`。**首轮不算变化**（没有上一轮就没有"变化"）—— 写入侧 `statFromStep` 给 `[]`，存量数据由读侧 `dropBaselineChanges` 抹平（必须在 filter/slice **之前**调，RV-15：否则每任务首轮把 41 个 path 全记成变化，从不变过的 `diy`/`guard`/`rules` 会显示成"变了 39 次 · 7.2%"） |
| ⚠️ 两处「请求预览」只有一处是真发 | **上下文树页**（ctxlab）的 `<>` 与「该步实际请求」= **真发字节**（同 `buildDelivery` / 流量日志）；**提示词页**（lab）的请求预览是**模版线**（`assembleSystem` 渲染 `_system.md` + AGENTS.md 链），它的 `requestNote` 已明确标注此事。别把 lab 的预览当成「会发出去的东西」 |
| ⭐ 变量树变更（步级 · 变量级） | 中栏「变量树变更（整棵树 + 标注）」：`lab()` 的整棵变量树（带当前值）+ 把**生效那条变更记录**标在命中节点上（行配色 = 增绿 / 删红 / 改黄；命中单元**之下**的节点也标，写「随 `chain` 变」）。命中判据 = `shared/context/changelog.ts` 的 `changeForNode`（同路径优先、其次最近祖先单元；**反向不成立** —— 变更单位是原子单元，叶子变了不代表整棵 `chain` 变了）。生效记录 = 选中的那条（`pickedSeq`），未选则取最后一条**有变**的。⚠️ 与「变更详情」是**两把不同的尺**：这块**步级 · 变量级**（点哪条记录标哪条，无"轮序→步序"的间接映射 —— 那正是"点击 ↔ 详情对不上"的根因），那块**轮级 · 文本级**（system/runtime 两份全文逐行比，读 steps.jsonl 的轮序）。 | ⚠️ 与另两块是**三把不同的尺**：本块**步级 · 变量级**（点哪条记录标哪条，无「轮序→步序」的间接映射 —— 那正是「点击 ↔ 详情对不上」的根因）、`system/runtime diff` **轮级 · 文本级**（发出去的字节逐行差）、「该步实际请求」**地面真相**（磁盘上那条请求原文）。
| ⭐ 该步实际请求（真发 · 流量） | 中栏「该步实际请求（真发 · 流量）」：把这一步**真发出去的那条 HTTP 请求**从流量日志（`log/network/<date>.jsonl`）捞出来 —— 本页重算只能证明"我以为会发什么"，流量日志才证明"确实发了什么"。挑法见 `shared/context/traffic-step.ts` 的 `pickStepTraffic`：只认 `turnId`（+ `taskUri`）**完全相等**；记录带步号时（##409 起 `stepSeq`，由 `traffic.noteStep` 在那一步请求前登记）按步号取**首试**那条，老记录退回"取 **ts ≥ 记录 ts 的第一条**"（changelog 那条写在 `prepareStep`、即该步请求**之前**）；⚠️ **不能按"第几条"挑** —— 老字段 `attempt` 是"本次运行内的往返序号"（跨步累计、重试也 +1），**既不是步序也不是重试序号**。同一步的重试链用 `groupByStep` 读（`attempts` / `retries` / `lastOk`）。找不到 → 明确提示（不编）。请求体默认只留首尾（`truncated`）→ JSON 解不开时如实说"被截断"并提示开「记录完整请求内容」。按钮「在流量页打开」= `trafficStore.focusWith({text: turnId, date, traceId})` + `navigate("traffic")`：目标页先按这两个**筛选条件**重查，目标那条才一定在结果里（否则定位会退化成"最近一次失败"，看着像点错了）。 |
| ⭐ 文本 diff（轮级 · 文本级 · 一份） | 中栏「system diff（逐行 · 真发全文）」读**投递快照**（`steps.jsonl` 的 `systemText`）算该轮 vs 上一轮的行级 diff（`foldDiff`：±3 行上下文、hunk 折叠；带旧/新行号）。`<>` 给该步真发的 system 参数全文（`help` + `vars`），说明走 info bar、不掺进正文。三块分工：变量树变更=变量级摘要、本块=文本级、该步实际请求=地面真相 |
